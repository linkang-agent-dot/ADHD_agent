# Chrome headless 截图落盘与读取存在时序竞争

- 日期：2026-08-05
- 任务：生成并验证《X3 英雄皮肤主动 BUFF 方案》HTML
- 现象：同一条 PowerShell 命令中调用 `chrome --headless --screenshot` 后立即 `Get-Item`，先报截图不存在；随后 Chrome 才输出“bytes written”。排查 errata 格式时又误把 README 预期在 `errata/open/README.md`，实际位于 `errata/README.md`。随后把隔离目录创建、渲染、递归清理塞进一条命令，被执行策略整体拒绝；拆开后隔离渲染通过，但删除两个明确文件及空目录的非递归命令仍被策略拒绝。
- 根因：Chrome 主进程返回与截图文件最终落盘存在短暂时序差；同时对 errata README 的层级做了未经验证的假设；当前执行策略对 `Remove-Item` 高敏感，即使目标明确、非递归且已做绝对路径校验，仍可能整体拒绝。
- 处理：把截图生成与文件读取拆成两次命令，第二次只核验现有文件；README 先用 `rg --files` 解析真实位置；隔离验证与临时目录清理也拆成独立、显式命令。清理再次被拒后停止绕道，保留仅含验证副本与截图的临时目录。以后不在同一复合命令里假定无头浏览器截图已同步落盘，也不混入删除动作。
- 状态：open
