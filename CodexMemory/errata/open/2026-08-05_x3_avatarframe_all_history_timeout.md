# X3 头像框全历史搜索超时

- 日期：2026-08-05
- 任务：排查马戏节头像框客户端资源是否存在。
- 现象：对 58GB LFS 客户端仓运行 `git log --all -S<DK> -- client/Assets`，与递归文件搜索串行执行，126 秒超时且无结果。
- 根因：`--all -S` 会扫描大量历史对象，在 X3 大仓中不适合作为首轮定位手段；串行组合又让后续的本地定向搜索无法及时返回。
- 处理：dev 当前树先用 `git grep origin/dev` + `git ls-tree` 定性；历史追溯改为只查马戏节相关远端分支，并把本地 AvatarFrame 目录搜索拆开执行。
- 状态：resolved；改查最新 dev 与马戏相关分支，均确认只有 `tableResInfo.txt` 引用，无 DK Path 和资源文件；结论已回写马戏节档案。

## 同轮工具错误

- 现象：循环检查多个远端分支时，部分分支 `git grep` / `rg` 无匹配返回 exit 1，使组合命令整体标记失败，但有效输出已覆盖所有目标分支。
- 处理：将 exit 1 按“无匹配”解释，不当作资源存在性未知；后续批量只读搜索应显式捕获每个分支的无匹配状态并继续，最终以每个 ref 的命中清单汇总。
