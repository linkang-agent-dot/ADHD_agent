# 复刻需求先固定 ID 角色映射

适用场景：用户说“新建一个活动”“复刻某活动”“老活动不变”，且上下文里同时出现多个相邻 ID。

## 必做映射

采取任何查改动作前，先在对话里明确写出：

`复刻源 source_id → 新活动 target_id；unchanged_ids 保持不动`

如果用户只给了源或目标之一，不要用知识库里的历史事故、旧活动或相邻编号自行补齐另一个角色。知识库负责提供背景和引用链，不能替代当前需求的 ID 语义。

## 本次案例

- 正确：`101830 → 101831；101829/101830 不改`。
- 错误链：先把 `101830` 当目标，再把 `101829` 自行解释成老活动，导致连续两次偏离。

## 实现验收

- 新增 diff 只包含 target 及其独立子配置。
- 对 source 与 unchanged IDs 做逐行哈希/字节级零改动断言。
- 汇报时继续使用 source / target / unchanged 三个角色，避免再次退化成含混的“新/老活动”。
