- [ ] 🔴**画布同尺寸 ≠ 内容同占位**（2026-07-28 马戏节大富翁地块实证，比下面那条更前置）：规格化脚本 `_规格化脚本.py` 的做法是 **trim 透明边 → contain 到画布 → 居中**，这等于**主动把内容撑满画布**。深海原件是美术画的、自带留白（内容 bbox 只占画布 28-39%）；马戏是 AI 出图被紧裁后再撑满（39-55%）。**两边都是 184×224「规格正确」，但内容大了一圈** → 棋格坐标照抄深海就挤成一坨（用户实机截图报"岛屿挤在一起"）。
  - **判据**：除了对 W×H，还要对 **①内容 bbox 尺寸 ②不透明像素占比**——与复用源同槽位资源比，占比偏离超 ~5pt 就要查。测法：`a=Image.open(p).convert('RGBA').split()[3]; a.getbbox()` + 不透明像素计数。
  - **修法**：目标不是"填满画布"而是 **内容 bbox ≤ 复用源族的包络**；**从最大原件重建**（别拿已压到槽位尺寸的图再缩，二次重采样会糊）；**站地面的物件要底边对齐**（只缩不对齐 = 一排浮空/陷地的高低差；深海地块底边 198-204 → 基线取 201）。
  - 脚本范本=`KB\产出-本地化与美术\X3\马戏节\地块与图标\_地块规格化_内容包络版.py`（含改前/改后/复用源三列占比对照打印 + 自动备份）。⚠️**凡过老 `_规格化脚本.py` 的透明资产都有同样隐患，不止地块**。
  - 只修真正超标的：马戏五张里 `start` 39.0%（vs 深海 39.3%）本就正确、`mystery` 仅超 4pt，**只动了 lucky/diamond/treasure 三张**——先按「超标幅度 × 占多少个格」排序再决定修谁（`lucky` 铺 12/24 格是头号，`diamond` bbox 高 223/224 顶满画布是单张最离谱）。
- [ ] **出图管线必含「槽位尺寸规格化」终步**：X3 美术尺寸铁律=与复用源同槽位资源**同尺寸**（HUD icon 124×136/道具 icon 256/地块 184×224/活动 bg 540×500/铭牌 752×192，见 reference_x3_art_resource_spec）。AI 出图默认 1024-2048 原图，落盘≠可用——判据=与任务 ref[0] 参考图同 W×H，批量规格化脚本（透明图 trim+contain/实底图 cover 裁切）见马戏节 `_规格化脚本`（马戏节实证 07-14：40 张里 38 张未规格化，用户凭"跟要投放的东西不符"直觉抓出）。
- [ ] **外显配置行建完必回填美术排产清单（配置↔美术两清单勾稽）**：纪念卡卡面/铭牌图/皮肤头图标这类"配置一行+图一张"的外显资产，最容易掉在配置清单与美术排产的夹缝里——配置建了行≠图进了出图批次（马戏节实证 07-14：纪念卡 81 卡面+铭牌 106 图两张漏排，用户抓漏才补）。收口时按"占位 DK 清单"反查出图批次，一一对上。

- **🔴x3-project 提交前必查暂存区，别只看自己 `git add` 了什么（2026-07-28 实证，当场翻车）**：主工作区常年有几十个别人/别的任务的在途改动，**其中 `client/Assets/Res/Config/ProtoGen/*.bytes` 可能已经处于「已暂存」状态**（谁跑过本地导表/`git checkout origin -- ProtoGen/` 都会把它们推进 index）。此时你 `git add <自己的文件>` 再 commit，**会把 27 个别人的 .bytes 一起打包进你的提交**——`git add` 只负责加，不负责清。
  - **正确姿势（每次 commit 前固定两步）**：① `git diff --cached --stat` 看**暂存区全貌**（不是 `git status`）② 出现 ProtoGen / `.claude/skills/*/memory/*.jsonl` 等无关项 → `git reset HEAD -- client/Assets/Res/Config/ProtoGen/` 踢掉，再 commit。
  - **已经误提交的修法**：`git reset --soft HEAD~1` → `git reset HEAD -- <无关目录>` → 重新 commit（**推送前发现就零成本**；推上去再修就要动远端历史）。所以**push 前一定先 `git show --stat HEAD` 复核这次到底提了什么**。
  - 这条与 [[reference_x3_project_repo]]「提交客户端改动时的暂存区排雷」是同一件事——那条写了要踢 ProtoGen，但没说清**它可能在你动手前就已经在暂存区**，导致「我只 add 了一个文件所以肯定只提了一个文件」的误判。
