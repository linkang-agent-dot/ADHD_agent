# 电商短视频换皮制作

把原片当作镜头与表演真源，把目标商品当作视觉真源。先按完整痛点拆模块，再决定复用、换皮或重建；已通过模块冻结，只返失败模块。

## 开工边界

- 个人项目只允许本地处理和用户授权的个人服务。禁止把素材、Prompt、参考图或视频提交到公司 GRFal、x3-media、media-worker、Morphix 或公司网络。
- 可以在本机只读学习公司工具的 Prompt 与实现逻辑，不得上传个人内容。
- 第三方原片只用于结构研究和用户授权范围内的创作。不得去除原作者/平台水印后冒充原创；仅在用户拥有生成结果且服务条款允许时处理生成器标识。
- 本 Skill 从“已有候选原片”开始。找片、排名和天镜数据属于素材雷达，不在本 Skill 内。

## 必要输入

开始生产前确认：

1. 本地完整原片，而非只看标题、缩略图或前几秒。
2. 目标商品正面、背面及必要结构图；每张图只放一个商品、一个视角、一个状态。
3. 要替换的痛点或卖点，以及不能改变的原片内容。
4. 目标时长、画幅、交付规格和可使用的个人生成后端。

没有先验商品定义时，先完整看完样片并回答“产品本身是什么”，不得从项目名或历史任务先入为主。

## 生产模块

### 1. 原片理解

- 完整检查画面、字幕、声音、商品和剪辑点。
- 输出：产品本身、痛点、痛点表达剧情、解决方式、核心逻辑、产品亮点、钩子类型和时间。
- 前15秒重点拆 `0–3s / 3–8s / 8–15s`，但成片生产按完整痛点段落拆，不按固定秒数硬切。

### 2. 骨与皮映射

为每个模块标记 `reuse / reskin / rebuild`：

- 骨：人物表演、场景、动作、机位、光线、运镜、节奏、真实剪辑点。
- 皮：商品外观、目标痛点、目标卖点、营销文字、冲突证据。
- 商品未出现且语义兼容的模块直接复用。
- 原片不存在的硬切、动作或剧情不得塞进 Prompt；需要新结构时单独重建模块。

### 3. 模块化拆片

- 一个完整痛点及其解决闭环是一段，不把一个痛点按任意秒数切碎。
- 每段只承担一个主要视觉任务：痛点、商品揭晓、证据、结构讲解、功能、结果或 CTA。
- 生成前把精确原片时间切成独立参考 MP4；禁止把整条30秒一次提交。
- 用 `scripts/project.py init` 创建项目清单和目录。

### 4. 逐镜头关键帧路由

读取并执行 `video-keyframe-router`。为所有 `reskin/rebuild` 模块填写 `ORIGINAL/T/F/SS/SE/MK + PC` 路线。

- 商品结构、无痕、手持接触、正背面、最大拉伸态等业务真源不得走纯文本。
- 关键帧只用于商品展示或高风险状态；无商品段不为流程完整而额外生图。
- 商品展示先出“场景内商品正确关键帧”，原尺寸验收后再生视频。白底商品图不能独自承担人物手持、动作和场景构图。
- 正面、背面、拉伸态分别出图，禁止多视角拼成一张参考图。

### 5. Prompt 与参考包

读取 `references/prompt-contract.md`。每个生成模块独立打包：

- 精确参考视频：只负责人物、动作、机位、场景、节奏和剪辑。
- 商品图/场景关键帧：只负责商品结构、颜色和目标状态。
- Prompt：先写保留项，再写唯一替换项、最小动作和禁止漂移项。
- 字幕、价格、Logo和卖点字默认后期添加，不让视频模型生成。
- 不额外描述或重塑人物；用户要求“复刻”时，人物以原片为准。

### 6. 模型与提交顺序

- `Seedance 2.0 Mini`：简单商品展示、单状态微动、低价方向验证；先有合格关键帧。
- `Seedance 2.5`：真人原片精确复刻、复杂接触、严格动作与机位保持的正式段。
- `PC`：已验收静态画面只缺节奏时，本地做推近、横移或裁切，不重新生成主体。
- 先提交最低风险段验证商品读图，再提交 CTA、接触段和复杂变化段。
- 一次只提交一段。生成结果失败时先修参考架构或拆镜，不叠加形容词继续赌。

模型价格与选择依据见 `references/production-modules-and-cost.md`。价格会变化，正式报价前重新核对账号页面。

### 7. 声音与包装

读取 `references/audio-post-qc.md`。

- 换皮原片默认保留连续原声底轨；不要逐段硬剪声道。
- 画面有人开口时优先保留对应原声，避免新声音与嘴形冲突。
- 原声文案与新商品不冲突时，用原片风格特效字承载新增卖点。
- 原声明确说出旧品牌、旧商品或冲突功效时，只替换冲突语音段，并保留环境声/音乐连续性；必要时再做嘴形同步。
- TTS 必须逐段生成、带情境指令、做本地 ASR 与听审。正式候选不得含重复句、错词、截断或无声中段。

### 8. 拼接与局部返工

- 统一帧率、分辨率、像素格式、时间基和音频规格后重新编码拼接；不要默认 `-c copy`。
- 已通过模块标记 `frozen`，后续不得重新生成或改画面，只允许统一转码。
- 静止帧只有在原片本来就是停顿或证据卡时使用；不得为了遮错插入突兀长静帧。
- 对失败模块局部替换，保持总时间轴和原片节奏。

### 9. 验收与成本

- 运行 `scripts/project.py validate --stage generate` 检查生成前门禁。
- 检查每段开头、中段、结尾和命名风险帧；接触表只用于定位，最终以原尺寸帧为准。
- 完整成片检查商品结构、人物一致、转场、字幕遮挡、声音连续、尾句重复、音视频时长与完整解码。
- 所有付费调用写入 `project.json.cost_entries`；失败调用也计费。
- 运行 `scripts/project.py cost`，分别报告生产成本和研发试错成本，禁止把两者混在一起。
- 完成后运行 `scripts/project.py validate --stage final`。

## 必交付文件

每个项目必须留下：

- `project.json`：模块状态、路线、参考、结果和成本真源。
- `换皮清单_骨与皮.md`：为什么复用、换皮或重建。
- `镜头路由表.md`：逐模块关键帧和风险帧。
- `prompts/` 与 `references/`：实际投喂材料。
- `output/final/`：唯一正式候选。
- `QC_REPORT.md`：视觉、声音和解码证据。
- `_目录说明.md`：FINAL、冻结、待返工和 DEPRECATED 状态。

## 完成条件

只有同时满足以下条件才可称为完成：

1. 全片已看完并识别真实商品。
2. 模块按完整痛点拆分，骨皮映射可解释。
3. 所有生成段有路线、参考角色和关键帧门禁。
4. 已通过模块被冻结，失败只返对应模块。
5. 成片音画连续、无重复尾句、可完整解码。
6. 成本区分生产与研发试错，并说明复用素材是否导致“本轮新增成本”低于“从零成本”。

军训无痕内衣实证与反例见 `references/case-military-training.md`。
