Feature proposal · UX specification

英雄皮肤
主动 BUFF 方案

把皮肤的被动说明，升级成玩家可主动安排时机的全局增益。拥有即解锁、换装不失效、多技能并行、每个技能独立计时。

方案

解锁条件拥有对应皮肤

01

方案结论

评审者最需要快速确认：玩家从哪里使用、使用后是否受换装影响、多个技能如何共存。

新增“皮肤增益”聚合入口。 玩家拥有带主动技能的皮肤后，即可在英雄主页查看并激活对应 BUFF；BUFF 在账号全局生效，切换英雄或皮肤不失效。不同皮肤技能允许同时生效，生效时间与冷却时间各自独立计算。

OWNERSHIP

拥有即解锁

能力归属“皮肤收藏”，不要求当前穿戴；未拥有时只展示预览与获取提示。

GLOBAL

全局持续生效

激活后作用于账号全局。换英雄、换皮肤、退出登录均不打断倒计时。

PARALLEL

允许并行

多个不同皮肤 BUFF 可以同时开启，不设置公共槽位或公共冷却。

INDEPENDENT

独立计时

每个技能保存自己的生效结束时间与冷却结束时间，互不覆盖。

02

机制与状态机

技能解锁后，玩家只需要理解三个核心状态；未拥有、网络失败、配置失效属于外围状态。所有倒计时均按服务器时间运行，离线期间继续流逝。

03

两个页面，各司其职

主页负责统一管理与使用；皮肤选择页负责解释“这个皮肤带来什么”。不要让玩家为了收一个到期 BUFF，在皮肤卡之间翻来翻去。

04

可点击状态演示

模拟多个技能同时存在：一个可使用、一个生效中、一个冷却中。点击激活后可推进时间观察独立变化。

皮肤增益已拥有 3 个主动增益

交互反馈原则

激活是低频且带较长机会成本的操作，因此保留一次确认；成功后技能卡立即切换为“生效中”，主页入口重新聚合计算可用数量——仅当没有其他可用技能时红点才消失。倒计时归零时原位切态，不弹窗打断玩家。

06

本功能不新增大面积美术包装，重点是把现有皮肤技能资源组织成稳定、可翻译、可追踪的一套表达。

美术与包装

  • 新增 1 个“皮肤增益”圆形入口图标，规格复用右侧“皮肤”入口
  • 聚合面板复用现有技能 TIP 框、按钮与倒计时样式
  • 每个技能优先复用当前皮肤技能图标；缺失时才补 IconDK
  • 三态只改变标签、按钮和环形进度，不为每个 BUFF 单独出背景
  • 商业化页统一写“拥有皮肤后永久解锁该主动增益”

数值方案边界

  • Duration 与 Cooldown 为逐技能配置变量，本案不擅自填写最终值
  • 评审至少校验：日均覆盖率、理论常驻率、玩家错过成本
  • 推荐起点：短收益配短冷却，强全局收益配长冷却
  • 同属性效果叠加规则拍板后，才能计算组合上限
  • 上线前产出单独数值表，并由数值负责人签字

服务端日志规范

  • activate：player_id、skill_id、skin_id、active_end_at、cooldown_end_at

  • 客户端埋点只做体验分析，服务端日志作为状态争议真源

07

验收标准

测试只要跑通这组用例，就能证明“拥有解锁、全局生效、并行独立”没有被实现歪。

功能验收

  • 拥有皮肤但未穿戴，仍可激活对应 BUFF
  • 激活后切换英雄与皮肤，BUFF 不消失、不重置
  • 两个皮肤 BUFF 可同时生效，结束时间互不影响
  • 单个 BUFF 生效中或冷却中不可重复激活
  • 退出重登、跨设备登录后倒计时与服务端一致
  • 离线期间生效与冷却时间继续流逝

界面验收

  • 主页红点只提示“存在可使用技能”，不提示纯倒计时
  • 聚合面板清晰区分可使用 / 生效中 / 冷却中
  • 技能 TIP 同时展示效果、生效时长与冷却时长
  • “皮肤使用中”与“增益生效中”视觉不混用
  • 确认弹窗明确本次生效时长与之后的冷却时长
  • 倒计时归零后，界面无需重开即可切换状态
08

评审待定项

交互骨架已经成立；标为“开发阻塞”的规则必须在进入实现前拍板，其余可在首批投放前补齐。

开发阻塞

① 时长与冷却口径

逐技能配置 X 小时；同时确认冷却从“激活时”还是“BUFF 结束时”起算。本文推荐后者。

开发阻塞

② 同效果叠加规则

不同技能可以并行已确定；若两个技能修改同一属性，还需确认数值相加、取高或互斥。

投放前确认

③ 首批开放范围

全量历史皮肤补主动技能，还是只从新皮肤开始；这会决定入口的首发内容量。

开发阻塞

④ BUFF 失效边界

限时/试用皮肤是否算“拥有”；皮肤到期、被回收或技能下线时，已激活效果如何处理。

联调前确认

⑤ 红点刷新频率

推荐登录、获得皮肤、激活成功、冷却结束时聚合刷新；不做每秒全局轮询。

投放前确认

⑥ 商业化表达

皮肤售卖页是否直接展示“拥有后永久解锁该主动增益”，以及是否标注每周期可用次数。

开发阻塞

⑦ 旧被动关系

原有皮肤被动属性保留并叠加主动 BUFF，还是由主动化替换；必须避免重复投放同一价值。

开发阻塞

⑧ 数据模型关系

推荐一张皮肤对应一个主动技能；若允许一皮多技或多皮共技，需要改用技能实例而非皮肤 ID 存档。

投放前确认

⑨ 全局作用域

列清覆盖的英雄、行军队列、采集/建造/战斗玩法，以及跨服场景，避免“全局”在实现中缩水。
