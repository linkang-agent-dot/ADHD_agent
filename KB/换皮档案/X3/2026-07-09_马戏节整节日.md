### 四条最贵的教训（全文见 must-check，这里只列判据）
1. **棋盘类背景**：细节走「四角裁切+上下横带」不是左右竖带（留空方向要跟前景形状对齐）；边缘母题不能和棋子同款；棋子靠明度差/色相差跳出来——**判据＝棋盘区明度对地块明度差 |Δ|≥60**
2. **画布同尺寸 ≠ 内容同占位**：老规格化脚本 `trim→contain→居中` 会把内容撑满画布 → 同 184×224 但内容大一圈 → 排版挤。**凡过该脚本的透明资产同隐患**
3. **x3-project 提交前必 `git diff --cached --stat` 看暂存区全貌**：主工作区暂存区脏是常态（今天撞两次：27 个 ProtoGen、2 个 DK），`git add` 只加不清
4. **`--reskin-residue` 会把源节日自己的 key 当残留报**：改错会破坏线上文案，先查「谁在引用它」

#### 🩹 开箱改造返工（07-29 用户实测「看不到进度条了」）
移植时**只比了节点树、没比组件与 layout 参数**，漏了三样。用户一句"进度条没了"暴露：

| 漏项 | 后果 | 正确值（照大富翁） |
|---|---|---|
| Slider 缺 `LayoutElement` | **Slider 被 HorizontalLayoutGroup 当成第一个布局项排进去 → 进度条整条消失** | `m_IgnoreLayout: 1` |
| HLG `ForceExpandWidth` | =1 会把子物体平分容器宽，项被压扁 | `0` |
| BoxGroup `pivot.x` | =0.5 时 `sizeDelta=count*120` **以锚点为中心向左右撑开，左半边跑出视口被裁 → 前一半档位看不见** | `0` |

🪤**通用规律（已进手术脚本注释）**：
1. **横滑列表的 content 一律 `pivot.x=0`**（左对齐）。pivot 0.5 + 代码定宽 = 一半内容长在视口外，症状是"只显示后半段"，极易误判成"数据没给全"。
2. **克隆 UI 子树必须比到「组件级 + 关键 layout 参数」，只比节点树不够**。本次比对脚本＝遍历子树逐节点列组件 guid + HLG/LayoutElement 关键字段，两边打平才算搬完（写进 `crafting_boxscroll_surgery.py`）。
3. **`LayoutGroup` 下混放"非列表项"（进度轨/背景/装饰）必须给它 `LayoutElement.IgnoreLayout=1`**，否则会被当成列表的一项参与排版。这也是 UIActvVoyage.cs:38 那条注释（ChildGroupController 会把 Slider 当成项）的孪生坑——**一个在代码层、一个在布局层，同一个"Slider 混在列表容器里"的结构代价**。

🪤**另一个自伤**：改 pivot 时正则写成 `--- !u!224 &\d+\nRectTransform:[\s\S]*?m_GameObject: {fileID: X}`，`[\s\S]*?` **跨了 doc 边界**匹配到上游别的节点，把一个无关 100×40 节点的 pivot 改了。**改 Unity YAML 必须先按 `^--- !u!\d+ &\d+` 切 doc、再在单个 doc 内做字段替换**，绝不能用跨行正则从文件级直接抓字段。（已回滚；`git diff | grep m_Pivot` 复核只剩预期的一处改动 + 一处新节点自带行）
