横 → 竖 改动说明（v0.1 我方初案）

区块（P2 节点）原位置（横屏 1920×1080）新位置（竖屏 1080×1920）理由 / 依据
宝物插槽 Slot左侧竖长条 485×733，纯展示顶部横条（demo 带 A/B 开关：可切到底部功能栏上方）竖屏没有左栏空间；横条保留「挖出→飞入插槽」核心反馈动线，上/下两案交给交互拍板
棋盘 DI/Grid8中央 800×800，中心 x+110 右偏居中归零，cell 放大（demo 6×6，cell≈162px）拆解结论#1：右偏是给左栏让位，竖屏必须归零；棋盘正方形天然适配竖屏（结论#8）
BtnsDigKey（挂机/图鉴/探测器）右侧竖排，比例锚 aMin.x=0.8/0.9（绑死屏宽10%）底部功能栏（拇指区）拆解结论#2：最硬横屏依赖——竖屏 1080 下该区塌缩到 ~108px 装不下 3 个 200px 按钮，必须首先重排
BtnRank / BtnReward / Btns右上双列 5+ 入口（排行/奖励预览/储蓄罐/成就/装饰）排行、礼包并入底部功能栏；其余二期收进「更多」或礼包页竖屏入口密度收敛，优先保核心动线；demo 中点击弹「二期演示」占位
资源条 Rss右上角横排（挖掘道具/探测器道具）顶栏第一行右侧顶部两行内收完；「+」保留礼包购买入口语义（Rss/BtnIcon→ShowPackages）
倒计时 Cuntdown右下角顶栏第二行右侧底部整段让给功能栏/拇指操作区
图鉴 UiDigKeyAtlas全屏翻书：左页类型列表 + 右页详情同屏对照上半屏固定详情卡 + 下半屏类型网格（点击切换，选中高亮）拆解结论#3：翻书是竖屏体验损失最大的一屏；此方案保住「同屏对照」，不拆两级页面
宝物飞行 FlyItem横向轨迹：棋盘→左 Slot（约500-700px，0.5s，EndScale0.45）纵向轨迹：棋盘→顶部插槽（demo 0.75s 贝塞尔）拆解结论#4：Slot 挪位后飞行改纵向，贝塞尔控制点与时长需重调（纵向距离短，原 0.5s 显慢→demo 实测取 0.75s 带回勾曲线）
背景 Bg/BgNew2080×1610 横构图demo 暂用原图 cover 裁切 + 上下渐变压暗拆解结论#5：竖屏 1080×1920 会露大量空白，正式版需出竖构图背景（美术需求项）
商店 UiDigKeyNewShop横向滚动，商品卡 444×648 竖长卡横排纵向滚动列表（挂机弹窗内二层页）拆解结论#7：横滑改纵滑；结算/探测器的 2 列 Grid 竖屏反而更优可保留
挂机领奖 OfflineReward横幅条 Content 左右拉满 1920，BtnShop@x=1626居中竖版卡片，「欢迎回来」+ 离线时长进度条 04:29:00/06:00:00 + 收益行 + 领取拆解结论#6：按 1920 写死必改；样式按老交互文档「挂机收益」弹窗范式；商店入口保留在弹窗内（沿袭 C-6 动线，注意 BtnShop 命名坑）
规则页 PlayRulePanel1 写死 1920×1080 全屏图文竖版居中卡片弹窗拆解结论#6：写死尺寸必改
⚠ 工具道具形态（两代差异）X2 v81 老版：兑换道具→选中→棋盘范围框→拖动定位→✓/✗ 确认 三段式本 demo = P2 v86 现行版：工具埋在棋盘格里，挖到即触发（整行/整列连锁）v86 明确的优化方向是「不需要兑换道具，挖掘时触发即刻生效」；demo 按现行版实现。两代方案取舍留作交互设计决策项（若恢复三段式，确认钮需落拇指区）
惊喜关卡链 SpecialTip预告横幅锚在「门上方显示屏」（横屏元素，800×100）顶部全宽横幅预告（前一关常驻）；惊喜关=紫色棋盘 + 关卡号隐藏（显示宝箱）老文档特殊关卡链：前一关预告「完成本关后即可进入」→ 惊喜关不显示关卡等级、用特殊配色；成本低观感好，demo 已实装（每第 3 关）
引导 C-10第1关 UIGuideMask 挖洞高亮，挖一格跳下一格同规则保留（光圈锚点改竖屏坐标）逻辑与横竖无关，直接平移；demo 已实装
