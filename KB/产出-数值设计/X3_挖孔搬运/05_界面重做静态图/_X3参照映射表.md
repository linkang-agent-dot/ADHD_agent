## 零、界面类型裁决（v3 新增 · 头等结论）

### 0.1 为什么必须先裁这一刀

v2 参照的 9 个 prefab（`UIActvExchange` / `UIActvDailyRank` / `UIMultiTierPack` / `UiActivityCommonRules` /
`UIPiggyBankContent` / `UIIdleIncome` / `UIActvCumRecharge` / `UIActvPreview` / `UIActvBattlePassScore`）
**全是 panel 子面板或整屏活动页的内容层，本身不带"壳"**（没有关闭 X、没有返回钮）。
照着它们画，画出来自然缺壳，v2 就自己补了一个「整屏页头（标题 + 倒计时 + 规则钮）」——**方向就歪在这里**。

X3 全仓实际只有两类界面外壳：

| 形态 | 全仓数量 | 判别特征 | 典型件 |
|---|---|---|---|
| **弹窗 popup** | **244** | 有关闭钮 `img_cm_zhizuo_guanbianniu` **104×104**，叠在调起它的界面之上 | `UIActvIdleReward` / `UIActvLuckyWheelProb` / `UIActvPuzzleTask` / `UIActvWishingPack` |
| **全屏页 fullscreen** | **103** | 无关闭 X，改为底部返回钮 `img_cm_anniu_return` **184×136**（`BottomPublicBtnEmpty` 现成件） | `UiActivityCommonRules` / 各活动主页 |

⇒ 挖孔这些子界面在 X3 里**全是弹窗**，开在「挖孔活动主界面」之上。

### 0.4 `04 玩法规则` 为什么裁成弹窗（这一刀有取舍，写清楚）

X3 里「规则/说明」有两种现成实现：

| 候选 | 形态 | 证据 | 代价 |
|---|---|---|---|
| `Activity/UiActivityCommonRules.prefab`（75 节点） | **全屏台账页** | 底部挂着现成件 `Common/PanelNew/BottomPublicBtnEmpty`（Return `img_cm_anniu_return` 184×136）→ 它自带返回钮，是全屏页 | 打开规则要**整屏切走**，挖孔主界面被盖掉；返回一次才回得来 |
| `Activity/UIActvLuckyWheelProb.prefab`（12 节点） | **弹窗** | Animation 1025×1217 + `img_dz_bg_3` + 关闭 X 104×104 + 竖滚列表 | 长文要竖滚；4 个页签得自己在弹窗里排 |

**v3 取 `UIActvLuckyWheelProb` 弹窗形态**，理由：规则钮在主界面右上（§2.1 的 `Info` 64×64），
玩家点它是「顺手瞄一眼」，不该整屏切走；且 X3 自己的概率说明（转盘）就是这么做的。
**正文行仍照抄 `UiActivityCommonRules` 的 `ItemTitle` / `ItemText` 两种官方模板**（行底 `img_ledger_bg_taizhangliebiao` 浅米纸 + fs26~27 `#5F4430`），
页签沿用它的 `img_ledger_anniu_taizhang_fenye` / `_fenye2`（h100，spacing −27.1）。
⇒ **只换壳、不换正文行**，落地时要改主意（切回全屏台账）成本很低：把弹窗壳换成
`img_ledger_bg_taizhang1` + `TitleBar` + `BottomPublicBtnEmpty` 即可，内容整块搬过去。

### 0.5 主界面 / 异星图鉴 / 探索目标选择器 / 结算 —— 为什么留全屏

| 屏 | 留全屏的理由 | 若要统一成弹窗，代价是什么 |
|---|---|---|
| **主界面** | 它就是被弹窗盖住的那一层。X3 活动主页范式（BG 944 活动大图 + 标题/倒计时/规则钮 + 底部功能栏）本来就是全屏 | 无意义——弹窗必须有个"底"，这层就是底 |
| **异星图鉴** | 内容量最大：40 件宝物 × 图标 + 名称 + 收集态，还要分组。920 宽内容区放 4 列（格子 200）已经很挤，滚动条会吃掉一列 | 每屏能看的宝物从 5×N 掉到 4×N，**翻页次数 +25%**；且图鉴是"逛"的界面，弹窗尺寸压抑体验 |
| **探索目标选择器** | 要在**同屏**里同时给出「棋盘缩略 + 候选目标列表 + 已选高亮」三块，这是选择器能不能一眼判断的前提 | 弹窗里塞不下三块并置，只能拆成两步（先选目标→再看棋盘），**多一次交互 + 丢掉空间参照**，探测仪的价值直接打折 |
| **结算** | 有过场动画/奖励飞入的表现位；X3 结算类（`UIActvPreview` 的大图位、各活动 Result）都是整屏铺开 | 弹窗把表现区压到 920×950，奖励飞入/大图展示没地方；且结算是流程终点，不需要"能看到下面那层" |

共通代价：这 4 屏 v1 已验收，**改壳 = 内容全部重排 + 重新验收一轮**，本轮不动。
