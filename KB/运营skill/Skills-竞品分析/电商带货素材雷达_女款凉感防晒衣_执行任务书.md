# 电商带货素材雷达 POC——女款轻薄凉感防晒衣

> 状态说明（2026-08-17）：本文件保留为“找片、留证、结构化拆解与候选筛选”的上游历史任务书，不再承载视频换皮生产。候选原片进入制作后，统一调用 `ecommerce-video-reskin`；旧项目内散落的逐次尝试流程不再作为新任务入口。

> 给执行 Agent 的一句话任务：用“女款轻薄凉感防晒衣”跑通一条真实的抖音素材雷达——发现公开素材，沉淀可核验台账，自动转写与结构化拆解，按统一框架聚类、筛选并建立可搜索素材池，最后输出每日候选清单和情报简报。

## 0. 开工指令

- 本任务是**真实 POC**，不是写概念方案。必须采到真实公开素材并留下可复核证据。
- 先小样本校准字段：抖音观察 5 条，确认数据可得性、播放器成功率与字段后再扩大。
- 不要把“高点赞/多人模仿”写成“赚钱”或“高 ROI”；没有投流费、成交、退款和成本数据时，只能称为**外部内容信号**。
- 看不到的数据统一填 `不可见` 或 `未获取`，禁止推测、补全或伪造。
- 遵守平台规则：不得绕过登录、验证码、频控、反爬或付费权限；不得去水印、破解下载或批量转载。公开页面无法自动采集时，切换到“登录态浏览器观察 + 人工录入 URL/可见指标”的降级路径，不准伪造已自动化。
- 素材只用于内部研究、结构拆解与原创改写，不直接复制受版权保护的画面、人物、配音、品牌标识或完整脚本。

## 1. 为什么选这个品

**样板品：女款轻薄凉感防晒衣**，不锁单一品牌，不替任何品牌做投放。

选择理由：

1. 卖点可视化：遮脸/遮手、透气、轻薄、凉感、防晒、帽檐、显瘦等都能通过动作或对比镜头表达。
2. 内容形态丰富：痛点演示、户外实测、通勤穿搭、前后对比、剧情、口播、测评均可采样。
3. 抖音公开样本充足，适合先把采集成功率、证据链和标签稳定性做扎实。
4. 合规风险低于内衣类，适合作为公开演示样板；同时仍能测试功效宣称、检测证据和版权风险识别。
5. 2026 年公开商品仍普遍使用 `UPF50+ / 凉感 / 透气 / 轻薄 / 大帽檐 / 户外` 等表述，素材池和卖点池足够丰富。

本 POC 不判断该品是否值得实际进货，只验证“素材发现 → 结构化理解 → 可执行情报”的上游能力。

## 2. 业务目标与成功标准

### 2.1 业务目标

把运营人员每天零散刷视频的工作，变成可复用的情报流水线：

```text
关键词/种子账号
  → 发现公开素材
  → 去重与留证
  → 语音/OCR/镜头拆解
  → 套统一带货框架
  → 聚类与趋势信号
  → 今日值得人工评估的素材
  → 进入原创改写/混剪/投流测试
```

### 2.2 本轮成功标准

- 采用三级判定，报告首页必须明确写其中一种，禁止含糊写“已跑通”：
  - **FULL PASS**：抖音不重复素材 ≥30，深拆 ≥10。
  - **DEGRADED PASS**：抖音不重复素材 ≥15，深拆 ≥5；可交付阶段性情报，但必须标明样本量边界。
  - **TECHNICAL POC ONLY**：未达到上述数量，只证明流水线可运行，不代表素材雷达已经稳定跑通。
- 所有素材都有平台、URL/可复核定位信息、采集时间、作者/账号、可见指标和证据路径；缺失字段明确标记。
- 能归纳出不少于 **5 类内容结构**，每类都能反查到原始样本。
- 输出 **Top 10 候选素材卡**；每张卡说明命中了哪些筛选规则、证据是什么、有哪些风险，并能反查原始素材。
- 任意一名新 Agent 只读本项目的 `README_运行手册.md`，可以补录新素材并重新生成简报。

## 3. 搜索范围

### 3.1 平台

- 抖音

优先使用用户已有登录态的受控浏览器。不要要求用户提供账号密码。页面加载不稳定时执行条件等待与有限重试，不把固定短等待后的暂态状态判成素材失败。

人工入口的最小输入文件固定为 `manual_import.csv`，UTF-8 编码，表头如下：

```csv
platform,video_url,locator_text,account_name,published_at,visible_metrics_raw,discovery_query,evidence_path,access_note
```

- `platform`、`account_name`、`discovery_query`、`evidence_path` 必填。
- `video_url` 必填；`locator_text` 同时填写，作为页面变化后的人工复核入口。
- `locator_text` 固定格式：`平台|账号名|发布时间或unknown|标题/首句前20字|证据文件名`，用于唯一定位和人工复核。
- `visible_metrics_raw` 保存页面原文，如 `点赞1.2万 评论356`；没有则写 `不可见`。
- 每条必须有截图证据；只有口述、没有链接/定位文本和截图的记录不得入正式台账。

### 3.2 时间范围

优先最近 30 天；若平台无法稳定按发布时间筛选，则采集“当前能发现的最新/高互动样本”，逐条记录实际发布日期或 `不可见`，不得声称它们属于最近 30 天。

## 4. 采集字段

台账一行一条素材。字段必须固定，建议同时保存 CSV 和 JSONL。

### 4.1 来源与证据

| 字段 | 说明 |
|---|---|
| `material_id` | 自增稳定 ID，如 `DY-0001`、`WX-0001` |
| `platform` | `douyin` / `wechat_channels` |
| `video_url` | 可复核分享链接；没有稳定 URL 时写可定位的分享文本并说明 |
| `platform_video_id` | 可见则填 |
| `account_name` | 作者/账号名 |
| `account_id` | 可见则填 |
| `published_at` | 原始发布时间；不可见不推测 |
| `collected_at` | 采集时间，Asia/Shanghai |
| `discovery_query` | 命中的关键词或种子账号 |
| `visible_metrics` | 点赞/评论/收藏/转发等；只填页面可见值 |
| `paid_or_ad_label` | 页面是否明确标广告/商品推广；未知写 `unknown` |
| `evidence_path` | 截图、缩略图或页面留证路径 |
| `access_note` | 登录态、页面限制、指标不可见等 |

### 4.2 商品与受众

- 品牌与商品名（若可见）
- 款式：短款/长款/修身/宽松/连帽/大帽檐/骑行等
- 价格与优惠（只记录画面或商品页明确出现的值）
- 目标人群
- 使用场景
- 用户痛点
- 核心卖点
- 功效宣称及证据类型：检测报告、标签、演示、口头宣称、无证据

### 4.3 视频结构

- 时长
- 前 3 秒钩子原意
- 钩子类型
- 逐段时间轴：`起止时间 + 画面 + 台词/字幕 + 功能`
- 内容结构：钩子 / 痛点 / 卖点 / 证明 / 信任 / 促单
- 主播形态：真人口播、画外音、剧情、测评、穿搭展示、混剪等
- 证明动作：吹风、泼水、灯照、拉伸、折叠、称重、遮脸/遮手、前后对比等
- CTA 与优惠表达
- 音乐、字幕、节奏、镜头数量
- 可学习的抽象结构
- 不可直接复制的版权元素
- 平台/广告合规风险

### 4.4 去重字段

- URL/平台视频 ID 精确去重
- 标题/转写文本归一化哈希
- 相似脚本组 ID
- 同源画面/搬运疑似组 ID
- `duplicate_of` 与判定理由

第一版不强求复杂视觉指纹；可以先用 URL、转写相似度、关键帧人工复核完成可靠去重。不要为了“全自动”牺牲真实性。

## 5. 统一分析框架

每条深度样本必须按以下框架输出，不允许自由发挥成散文：

1. **卖给谁**：年龄/生活状态/场景，不凭外貌臆测敏感属性。
2. **为什么现在停下来**：前三秒用了什么视觉、台词或冲突。
3. **唤起什么问题**：晒黑、闷热、普通外套不透气、骑行遮不全、穿着显胖等。
4. **给出什么承诺**：防晒、凉感、轻薄、透气、修身、全方位遮挡等。
5. **怎么证明**：实测、对比、细节特写、检测报告、口碑、价格锚点；区分事实证据与纯口播。
6. **如何降低决策成本**：价格、优惠、尺码、颜色、适用场景、退换承诺。
7. **如何促成下单**：限时、库存、赠品、组合装、明确 CTA。
8. **视频生产难度**：场地、演员、道具、拍摄和后期复杂度。
9. **原创迁移空间**：可以借鉴的结构、可替换变量、不可复制元素。
10. **可信度与风险**：夸大功效、伪实验、绝对化用语、品牌/肖像/音乐/完整脚本版权。

## 7. 执行阶段

### 阶段 A：可得性验证

1. 在抖音用 3 个核心关键词搜索。
2. 首批记录 5 条样本，并记录页面加载尝试次数与最终状态。
3. 写清能看到哪些指标、能否拿到分享链接、能否读取发布时间、能否合法保存视频。
4. 输出 `00_平台可得性记录.md`，再决定自动采集与人工补录的比例。

### 阶段 B：小样本校准

1. 建字段 schema 和台账。
2. 深拆 10 条素材。
3. 用首批结果校准标签、重复判定和风险字段。
4. 先人工抽查转写、OCR、前三秒钩子和卖点，不通过不得扩量。

### 阶段 C：扩大采集

1. 扩至至少 30 条唯一素材。
2. 保存必要证据，不保存无授权的整批原视频副本。
3. 去重并形成相似脚本/同源素材组。
4. 所有自动步骤都必须支持断点续跑，并记录成功、失败与原因。

### 阶段 D：生成情报

输出：

- 今日/本批新增素材概览
- 高频卖点与高频钩子
- 抖音内部不同账号、内容结构与卖点表达的差异
- 新出现或集中出现的表达
- 值得人工优先看的 Top 10
- Top 10 候选素材及筛选理由
- 风险素材与不建议跟进原因

### 阶段 E：形成标准候选素材卡

为 Top 10 各生成一张可检索、可交接的候选素材卡：

- `material_id` 与原始证据
- 商品、平台、账号、发布时间和可见指标
- 钩子、痛点、卖点、证明动作、内容结构和 CTA 标签
- 命中的筛选规则及进入 Top 10 的理由
- 内容生产难度与合规/版权风险
- `人工状态`：待查看 / 已查看 / 不采用 / 交给下游

素材雷达只负责提供结构化候选和检索入口，不生成原创脚本，不决定生产方式，不根据后续投流数据评价素材。

以下任一项不满足，不得声称“上游素材系统已跑通”：

- 没有真实 URL/定位信息和截图证据。
- 把搜索结果摘要或商品页当成已经看过的视频。
- 把公开互动指标解释为销量、GMV、ROI 或利润。
- 30 条里大量是同源搬运而未去重。
- AI 标签无法回到原始台词、字幕或画面证据。
- 没有平台采集失败的降级路径。
- 未按 FULL PASS / DEGRADED PASS / TECHNICAL POC ONLY 明确判定结果。
- 人工导入记录缺少稳定 URL，且同时缺少规范 `locator_text` 或截图证据。
- 只交报告，没有结构化台账和可复跑脚本。
- 为了采集绕过平台安全机制或保存/传播未授权整片。

## 12. 推荐开工顺序

```text
1. 阅读本任务书和四份复用资产
2. 建产物目录与空 schema
3. 抖音采 5 条做可得性与播放成功率记录
4. 完成 10 条深拆并校准标签
5. 人工抽查后扩至 30 条
6. 去重、聚类、生成情报简报
7. 产出 Top 10 候选素材卡并验证筛选排序可复现
8. 按验收门禁自检
9. 派 task-checker 对交付物守门
10. 写 _目录说明.md 并向主对话回报：结论、实际改动、验证、未决项、下一步
```
