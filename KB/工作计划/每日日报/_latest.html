详细版本

① X3 挖孔「异星探索」·交互形态返工

上午一开工先推翻了昨天的静态图方向。原因：v2 把商店/排行/礼包/规则/存钱罐/挂机都画成了「独立整屏页」（自带标题+倒计时+规则钮），但全仓 prefab 一扫就坐实错了——我们参照的那 9 个 prefab 全是 panel 子面板，自己没有壳，照着画必然缺壳，v2 就自己补了个整屏页头，方向从根上歪了。

  • X3 真实只有两类形态：弹窗 244 个（带关闭 X）／全屏页 103 个（带返回钮 184×136）。挖孔这些子界面应当是叠在活动主界面之上的弹窗。
  • 出了 v3 静态图，10 屏全改弹窗形态，壳尺寸分三档：中号 1025×1130（挂机、存钱罐，不滚）／大号 1025×1213（其余 7 屏，竖滚）／无壳（通行证只做 HUD 入口卡）。
  • 给客户端的一句话结论：除挂机/存钱罐外其余一律「大号壳 + LoopVerticalScrollRect」，正好是现成结构，克隆即可。
  • 顺带纠了我上一轮给错的参照物：玩法规则原来参照的那个 prefab 其实是全屏页，已改判为弹窗。
  • 图鉴/探索目标选择器/结算 4 屏维持全屏，代价评估也一并给了（改弹窗会少列、翻页 +25%、丢奖励飞入动画位）。

② X3 挖孔·交互 demo 收口成「需求差异集」

逐屏拍板了「哪些屏根本不用做」，demo 定位随之变了：凡直接复用 X3 老模块的屏，demo 里不再画界面，点入口直接弹 tips 写明复用哪个 prefab + 关键差异。demo 从此 = 需求差异集，接手 GUI 的人看 tips 就知道克隆谁。

  • 删界面转 tips 的 5 屏：直售/补给礼包（无限购）、排行榜+名次奖励（同页竖滚，名次奖励是下滚段不是第二页签）、兑换商店（删掉「活动结束后将被回收」那段文案）、存钱罐（本期先不做）。
  • 保留并重做的：挂机领奖（不算复用 OK）、玩法规则（界面保留但也弹 tips）、成就礼包（改成通关数 1/5/10/15/20 节点、15 档平铺、每档每人限购 1 次、加「已购」置灰态）、通行证（只留 ICON，去掉等级/进度条/宝箱）、关卡奖励预览（分段页签 + 打开自动定位当前关）。
  • 复验方式不靠 agent 自述：headless 逐个调 12 个入口，零 JS 报错，5 张 tips 卡 + 7 个界面各自正常。
  • 遗留：存钱罐（往后放）、关卡奖励预览每行只显 2 个奖励图标、成就礼包价格还是演示阶梯（真表没价格字段，等数值定）。

③ X3 挖孔·活动包装与程序 prefab 对齐

下午的验收意见是「图鉴太黑、整体 UI 看着很呆」。判定「呆」的根因是全用通用件（浅米羊皮纸 + 木质档位行）套「异星探索」这个科技题材，必然平、闷、无记忆点。

  • 治法四条可验证的改动：换 X3 现成科技风套件做主题底板／补层次深度（分隔线、内阴影、高光边）／强调色统一到青绿（金色只留给价格和奖励）／主界面棋盘区加环境光与扫描线。图鉴单独重出：提亮 + 星图感底 + 宝物卡品质边框，但保留已认可的「上详情 + 下网格 + 双页签 + 底部进度条」结构。
  • AI 出了竖版主背景（1080×1920，替掉原来 P2 横图裁的露白版）、扫描线可平铺件、弹窗青/金装饰环；原则是「P2 已有的资源一概不重出」，先出覆盖清单再决定生成哪些。
  • 与程序侧汇合：对方用 html-to-ugui 把我们的 HTML 转成了 14 个 UGUI prefab，并建了挖孔专属图目录（25 张按 X3 命名规范）；他还把整代皮按科技风重指了 87 处、新增 6 个装饰节点，让这轮的包装件真被引用上。
  • 我这轮做的是把他们抽走的旧版素材换成最新版（背景横→竖、补三个新件），替换沿用原文件名保证 prefab 引用不断。
  • 一处自我纠正：仓内那份图-件映射表我当初用哈希反查生成，实际有 11 组与 demo 声明不一致——根因不是哈希不准，是本来就不该反查（真源就在 demo 里，只是我的正则只抓到三分之一的声明块）。已改成从声明块直接生成。
  • 明确一条长期结论：借别的活动（机甲/陨石战/记忆）的皮只能做到「不呆、有主题倾向」，「异星探索」专属包装仍需美术出整套，这条继续挂在美需清单。

━━━ ① X3 挖孔「异星探索」·交互形态返工 ━━━
上午一开工先推翻了昨天的静态图方向。原因：v2 把商店/排行/礼包/规则/存钱罐/挂机都画成了「独立整屏页」（自带标题+倒计时+规则钮），但全仓 prefab 一扫就坐实错了——我们参照的那 9 个 prefab 全是 panel 子面板，自己没有壳，照着画必然缺壳，v2 就自己补了个整屏页头，方向从根上歪了。
· X3 真实只有两类形态：弹窗 244 个（带关闭 X）／全屏页 103 个（带返回钮 184×136）。挖孔这些子界面应当是**叠在活动主界面之上的弹窗**。
· 出了 v3 静态图，10 屏全改弹窗形态，壳尺寸分三档：中号 1025×1130（挂机、存钱罐，不滚）／大号 1025×1213（其余 7 屏，竖滚）／无壳（通行证只做 HUD 入口卡）。
· 给客户端的一句话结论：除挂机/存钱罐外其余一律「大号壳 + LoopVerticalScrollRect」，正好是现成结构，克隆即可。
· 顺带纠了我上一轮给错的参照物：玩法规则原来参照的那个 prefab 其实是全屏页，已改判为弹窗。
· 图鉴/探索目标选择器/结算 4 屏维持全屏，代价评估也一并给了（改弹窗会少列、翻页 +25%、丢奖励飞入动画位）。

━━━ ② X3 挖孔·交互 demo 收口成「需求差异集」 ━━━
逐屏拍板了「哪些屏根本不用做」，demo 定位随之变了：凡直接复用 X3 老模块的屏，demo 里不再画界面，点入口直接弹 tips 写明复用哪个 prefab + 关键差异。demo 从此 = 需求差异集，接手 GUI 的人看 tips 就知道克隆谁。
· 删界面转 tips 的 5 屏：直售/补给礼包（无限购）、排行榜+名次奖励（同页竖滚，名次奖励是下滚段不是第二页签）、兑换商店（删掉「活动结束后将被回收」那段文案）、存钱罐（本期先不做）。
· 保留并重做的：挂机领奖（不算复用 OK）、玩法规则（界面保留但也弹 tips）、成就礼包（改成通关数 1/5/10/15/20 节点、15 档平铺、每档每人限购 1 次、加「已购」置灰态）、通行证（只留 ICON，去掉等级/进度条/宝箱）、关卡奖励预览（分段页签 + 打开自动定位当前关）。
· 复验方式不靠 agent 自述：headless 逐个调 12 个入口，零 JS 报错，5 张 tips 卡 + 7 个界面各自正常。
· 遗留：存钱罐（往后放）、关卡奖励预览每行只显 2 个奖励图标、成就礼包价格还是演示阶梯（真表没价格字段，等数值定）。

━━━ ③ X3 挖孔·活动包装与程序 prefab 对齐 ━━━
下午的验收意见是「图鉴太黑、整体 UI 看着很呆」。判定「呆」的根因是全用通用件（浅米羊皮纸 + 木质档位行）套「异星探索」这个科技题材，必然平、闷、无记忆点。
· 治法四条可验证的改动：换 X3 现成科技风套件做主题底板／补层次深度（分隔线、内阴影、高光边）／强调色统一到青绿（金色只留给价格和奖励）／主界面棋盘区加环境光与扫描线。图鉴单独重出：提亮 + 星图感底 + 宝物卡品质边框，但保留已认可的「上详情 + 下网格 + 双页签 + 底部进度条」结构。
· AI 出了竖版主背景（1080×1920，替掉原来 P2 横图裁的露白版）、扫描线可平铺件、弹窗青/金装饰环；原则是「P2 已有的资源一概不重出」，先出覆盖清单再决定生成哪些。
· 与程序侧汇合：对方用 html-to-ugui 把我们的 HTML 转成了 14 个 UGUI prefab，并建了挖孔专属图目录（25 张按 X3 命名规范）；他还把整代皮按科技风重指了 87 处、新增 6 个装饰节点，让这轮的包装件真被引用上。
· 我这轮做的是把他们抽走的旧版素材换成最新版（背景横→竖、补三个新件），替换沿用原文件名保证 prefab 引用不断。
· 一处自我纠正：仓内那份图-件映射表我当初用哈希反查生成，实际有 11 组与 demo 声明不一致——根因不是哈希不准，是**本来就不该反查**（真源就在 demo 里，只是我的正则只抓到三分之一的声明块）。已改成从声明块直接生成。
· 明确一条长期结论：借别的活动（机甲/陨石战/记忆）的皮只能做到「不呆、有主题倾向」，「异星探索」专属包装仍需美术出整套，这条继续挂在美需清单。

━━━ ④ X3 挖孔·活动可开 + 配置表结构评审 ━━━
· 活动现在**能自己开起来**：给了真时间窗（2026-08-01 起 120 天、不循环），不用后台部署也不用 GM，表一加载就在窗口内；活动进普通活动列表，规则弹窗、顶部资源条（能量铲 + 核心电量）都在。
· 撞到一件必须记的事：活动**已被定名「异星探索 / Alien Expedition」**，且配套一整套科技风词汇（挖掘道具=能量铲、挂机货币=核心电量、商店=无人机补给站、图鉴=异星图鉴，三个宝物=星图终端/密封补给箱/棱镜钻核）。我原先写的「挖宝寻踪」已作废，后续策划案与美需都统一用这套名字，不要再出第二套。
· 顺手补了个真缺口：两个挖孔道具此前一个多语言行都没有，运行时顶部资源条会是空白，已补齐并去掉重复录入。
· 出了一份**配置表结构评审**（自包含 HTML，表里数值全是脚本从真表现读的），四张自有表逐列标状态 + 引用链全展开 + 结构缺口清单。三条最要紧的缺口需要拍板：
  1) **工具触发机制的表结构是错的** —— 现在是「把工具埋在格子里」（服务端也照这个实现），但从 P2 真表得出的定案是「按挖掘次数窗口概率投放」，两套模型对不上，关卡表缺 4 类字段，三种工具道具也还没建。
  2) **过第 3 关会卡死** —— 服务端只做了 levelId+1，循环关/负数奖励关一律没处理。
  3) **主表只有 5 个字段，装不下已有文案的模块** —— 探测仪消耗、储蓄罐的「每 N 铲存 1」、商店、成就礼包档位限购、纪念卡关卡映射、图鉴里程全无落点。这条最费工，得先逐个定「开新表 vs 复用 X3 现成表」，两者差一个量级的工作量。
· 另回答了「挂机产出表能不能并进主表」：**不建议合**。X2 真界面里「充电奖励」弹窗就是把挂机表逐行渲染给玩家看的（关卡/固定奖励/概率获得三列，4 档 3→5→8→15/分），一行 = 界面一行；合并会出现双层分隔符、且事实上逼你砍掉分档，而分档正是「推关越深挂机越香」的钩子。顺带发现概率道具真表是 5 种，我们只规划了 3 种，这条要和工具机制一起定。

━━━ ⑤ X3 马戏节「限时抢购」·界面文案硬伤清零 ━━━
上午到下午把这个活动的显示层问题逐条打掉，全部有实机取证：
· 「剩余 N」买完就消失 → 改按是否在场内判，已修。
· 「距开抢」和「抢购中！」同屏自相矛盾 → 根因是 X2 时代烘死的多语言 key 还挂在倒计时节点上，从没被赋过值；已在停止计时时连 key 一起清，并全量扫描确认整个界面剩余可上屏的烘死 key 全部有主。
· 「剩余: 剩餘: 2000」标签重复 → 补绑定并清空，已修。
· 九格购买钮换成通用采购组件（价格、累充点挂件、购买流程全交给它），钻石档不再显示成「立即完成/免费」；售罄与未开抢态改成同形状置灰；「价值 $35.98!」误显已隐。
· 「即将开卖」补上限购数，文案为「即將開賣 每場限購1次」。
· 活动标题与说明原来是空的 —— 定位到是搬运时就欠的多语言债（那两列要放 key，放中文字面量导出后就是空），已补齐并改掉文案里已经砍掉的「助力/分享」表述。
· 规则文本读不出来 —— 那一行在表里占了 13 个物理行（换行写成了真换行），客户端只读到第一段；已重建为单行、换行改用字面 \n。
· 补了钻石档的限购闸（原来是 0，等于可以无限买，和之前 IAP 档踩的同一个坑）。
· **分工调整（今天定的）**：GUI 表现由我出说明书 + 管代码关联，prefab 手调归你。原因是我这边反复猜视觉猜错了 5 轮，纯属浪费。同时给了「按钮改大小该改哪个值」的说明（改 Transform Scale 白改，会被组件在 OnEnable 覆盖回去；改 Rect 宽高字号不跟着缩；正解是改组件里的缩放值，但它不支持多选，九格批量交给我一条命令刷）。
· 这轮吃透了本地验配置改动的三层链路：改表 → 导表（产物落的是中间目录，**不会自动到客户端**）→ 手动同步产物 → 退出重进（运行时是启动预载，刷新资源不重载）。「导表 EXIT=0」只代表生成成功，不代表客户端读得到。相关的起服、双服重编、改代码要先刷新再编译等坑都已写进知识库。
