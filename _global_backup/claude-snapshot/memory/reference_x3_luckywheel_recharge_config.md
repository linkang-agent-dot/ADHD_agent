# X3 大转盘 + 累充 配置链速查（2026-07-21 尼罗实操沉淀）

## 大转盘（ActvType=10）配置链
ActvOnline(type10).ContentID → `ActvLuckyWheel__ActvLuckyWheel.tsv`（同ID行）：
- Consume=抽奖券道具 / RewardGroup=**奖池组**(→ActvLuckyWheelReward) / OtherRewardGroup=累抽里程碑(→ActvLuckyWheelOtherReward,NeedTime=次数,RewardID=宝箱) / ServerRank=本服排行榜ID
- 奖池表列：`[0]ID [1]Group [2]ItemID [4]ItemNum [5]Weight [6]SReward超级大奖 [7]Order`；**总权重惯例=10000（权重即万分比）**

## ⚠️ 转盘硬性10格，只能换不能加
- prefab `UIActvLuckyWheel.prefab` 的 Turntable/Content 下**预置 Item~Item10 正好10个**；指针角度 = `360 / 格子数`（**int整除**，UIActvLuckyWheel.cs:389）——11格时 360/11=32 与图标排布错位，指针指到格子缝。
- 佐证：全表19个奖池组无一例外10行。给转盘加新奖励=**替换现有一格**（连Weight一起调，注意猫眼石币类兑换币的产出期望别砍崩兑换商店）。

## 累充（ActvType=5）插新档是安全的
- 档位=ActvTask TT=902 行（[4]阈值充值点 [8]RewardID），奖励=Reward同号组。
- **充值点汇率=10点/$1**（真源 `Pack__PackPrice.tsv` Points列：$4.99=50点）。惯例档位：100/400/1000/2000/4000/7000/10000/13000/16000/20000点 = $10~$2000，**没有$500档**。
- **客户端 UIActvCumRecharge 按门槛升序排列、tab按档位数动态克隆**（Sort by CActvTask.Count）→ 插入乱序ID的新档（如59411阈值5000）显示位置正确，档位数可以不是10。

## ⚠️ Reward表[4]名字列是假标签
Reward__Reward.tsv 的道具名列是复制残留、**不进游戏也不校验**——尼罗累充59401-59410名字列写着钻石/VIP点数/神秘金属，实际ItemID全是1128女王恩典卷。**查投放认ItemID列([3])，别信名字列**。
