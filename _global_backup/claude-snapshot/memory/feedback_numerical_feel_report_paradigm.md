# 「数值感受报告」范式（2026-07-31 寻宝103101案确立，用户认可）

**Why**：用户说"模拟玩家跑一轮感受一下ROI"时，要的不是 EV 表格，是**决策用的体感**。寻宝案产出（`KB\产出-数值设计\X3_马戏节\寻宝ROI模拟_20260731.html`）被用户评"思路和出报告的感觉很对"，此文件即该案范式提炼。

**How to apply**（五步，顺序即优先级）：
1. **机制实证到代码级**——读服务端实现钉死公式（整数除法/保底/计数口径），不按配置表或经验猜。数字敢具体（"$445、恒定13星"），叙述才敢简单。
2. **估值口径先统一**——每个道具单价两条独立路径交叉验证（[[reference_x3_roi_valuation]]），口径干净后面所有数字才互相咬合。
3. **一条主线挂所有信息**：主线=**一个玩家的钱包**（从$0到目标，每步花什么拿什么）。查到的任何事实都翻译成"对这个钱包意味着什么"再放入，翻译不过去=砍掉。
4. **每个数字配体感翻译**：不说"E=8.73"，说"前7抽是白抽期，星都在8-12抽出"。数字+体感两个都给。
5. **分层交付**：10秒版（4块stat牌）→1分钟版（交互图表）→5分钟版（可折叠实录）。改造方案必带多档对比曲线（含"不改"基线），让拍板变成选择题。

**产物形态**：自包含HTML本地打开（[[feedback_html_open_local_not_artifact]]），图表走 dataviz skill 规范；模拟器归档 `x3-numerical-design\scripts\` 复用（pool_roi.py / pioneer_city_sim.py 已是先例）。
