# 数据分析方法论手册（跨游戏通用·冷启动接管）

> 来源:P2/X2/X3 三游戏 30+ 份历史节日回归报告提炼(2026-07-22 系统归纳)。
> **复现度标记**:✓✓✓=三游戏各自独立复现(最硬,当铁律)；✓✓=两游戏；✓=单游戏成型可复用。

## 〇、最核心的结构:回归=模块装配,不是填一份固定模板的策划案（用户2026-07-22定）

**一次回归的骨架不是预设章节,是"这个活动做了哪些设计动作"拼出来的;不同活动动作组合不同(深海=大富翁+连锁+装饰+周卡+拜访 / 世界杯=竞猜+开箱+皮肤+BP)。**

**★模块的本质 = 一个设计动作,它在回归里回答"这个动作有没有达到它的目的";而目的决定了效果该用哪个指标验证(靶)。** 加排行榜→目的是刺激头部竞争→靶=顶端玩家付费(不是整体付费率);加阶段奖励→目的是推玩家跨节点→靶=节点转化率。**所以口径/范围是被"要验证的效果"倒推出来的,不是自选的——这是"范围瞎搞"的根治:问题决定口径,不是拍脑袋定范围。**

所以任何回归三步走:
1. **建框架(沟通阶段第一件事)**:先搞清这个活动**做了哪些设计动作**(每个动作=一个待验证模块)——问策划 / 查 ActvOnline 配置 / 看排期甘特 / 看往期同节日。产出「本次模块清单」= 报告目录。**别急着查数,先把框架和用户对齐。**
2. **选模块 + 认靶**:清单里每一项去 [[reference-data-analysis-module-registry]](模块库)对号,先认清**它的靶指标**(效果该体现在哪);库里没有=新动作,现建卡(必须先想清它的目的和靶)。
3. **套规则**:逐模块按卡的靶+口径走(口径由靶倒推,**禁承袭上一个模块的范围**),回答一句"它有没有达到目的";最后用「节日总体」卡把各模块串成净增归因。

> 报告体裁只是框架的粒度选择:模块清单只有 1 项且要深挖=单模块报告(C,先写「回归框架.md」目的/数据/优化三列);清单是整个节日全模块=节日整体(A,P2 走 `generate_event_review` skill 改 input_data.json)/多模块诊断(B,每段带[正常/关注/异常]判词)。**框架先行,体裁跟着框架走。**

## 一、认知层（怎么想·思维模型）

1. **先给活动下判词:拉宽(付费率/渗透)还是拉深(ARPPU/客单)** ✓✓✓。所有结论围绕此判词。模板句:"价值在提升付费率(让更多人付费),而非提升ARPPU"。推币机=经典"宽口浅底"(付费率全场第一/ARPPU垫底)。
2. **效果拆解=广度×深度**:`付费玩家ARPU = 付费率(广度) × ARPPU(深度)`,三者自洽,**付费玩家ARPU最准**(同时含广度深度)✓✓✓。据此把模块病灶分四类对号入座决定怎么救:
   - ①**广度型双降**=核心引擎 → 排期/玩法救
   - ②**纯广度崩·搭车**(付费率大跌ARPPU持平/涨)=热度不够没人进场 → 靠做旺引擎带
   - ③**纯深度崩·配价**(ARPPU腰斩付费率没动)= 单独重配档位
   - ④**健康**(广度降深度涨自抵消)
3. **一切增量对照"自然衰减基线",功劳是"逆转衰减"不是"绝对增长"** ✓✓✓。成熟服天然衰减(周环比-26~-30%),看绝对值必误判。要算"实验组vs对照组净差"或"实际vs按自然增速的预期"。
4. **设计预期 vs 实际 = 差值归因,不罗列实际值** ✓✓✓。开工先找设计文档的预期数(档位/投放量/坑深/覆盖率目标),没有就先反推一个,再算gap,差距最大层=根因。反复结论="方向没错,是门槛校准跟实际活跃对不上",而非推翻设计。
5. **根因分层钻,不停表象;主动列"已排除的假设"** ✓✓✓。"付费率降"继续拆渗透/深度/活跃哪个掉;写清哪些竞争假设被数据否掉(钻石存量/养成饱和/全面饱和逐一排除),证明结论收敛非拍脑袋。范式=累充超投橙碎片→积压→消耗率89%→66%→碎片礼包需求塌方。
6. **替代vs叠加:节日礼包收入可能"挪账"了存量消费,净增≠礼包直接收入** ✓(X3)。礼包直接+$9.67但非节日消费低于预期-$7.57,净增只剩+$2.10。
7. **参与率/覆盖率必对标,不看绝对值** ✓✓✓。跟①历史同类新服基准②同期其他节日③常规核心玩法 三锚点比才判正常/异常(14.5%单看像低,对标同期节日14.8%后判"正常")。
8. **低触达≠玩家不爱**:低参与先怀疑入口/门槛,而非内容 ✓✓(集卡"接触率是第一障碍";送花"付费壁垒削弱社交")。
9. **头部依赖是常态,但设健康区间当红线**:鲸鱼/超R依赖度**健康区间50-70%**,超过标风险 ✓✓✓。
10. **小样本鲸鱼敏感性**:新服付费个位数,"单个大R即可改变数据,需多服验证",对照组主动排除鲸鱼服 ✓✓。
11. **门槛校准是隐形杀手**:深度提升≠付费提升;BP满级门槛太高→深度没转成等级/满级/付费;瓶颈永远在首次转化/门槛,不在升级意愿/奖励结构 ✓✓。
12. **同模块有多种合法成功模式,别用一把尺子量** ✓(P2):"广覆盖高频型"(挖矿:分层SKU+复购)vs"窄覆盖高客单型"(送花:高R情感消费)。评价前先认属哪型。
13. **双基线锚定**:每份报告对标"上一期(环比看节奏)+去年同期(同比看趋势)" ✓✓✓。
14. **事件型模块归一化**:供给量随时间变(场次/SKU数/开放天数)先归一化到单事件再判走势 ✓(竞猜)。

## 二、标准层（怎么算·口径纪律）

### 通用口径（全游戏统一）
- **三件套缺一不可,逐档逐子活动都带**:付费率/ARPU/ARPPU ✓✓✓。模块表列序:收入/买家/**付费率**/ARPU/ARPPU/复购/max。
- **三个ARPU口径可信度排序(权威)**✓✓✓:①**付费玩家ARPU=模块流水/全部付费玩家**⭐最准(含广度+深度,分母稳)②ARPPU=流水/该模块买家⚠️会骗人(掩盖"买的人变少")③付费率=付费人/DAU❌跨期不可比(累计vs日均给相反方向),只看同期趋势。评效果一律优先①。
- **ARPU分母=当日总付费人数**(非节日付费人数)✓✓✓;判趋势/衰减回升用**/DAU口径**(用/付费人数即ARPPU,会消掉"付费人数涨"得反结论)。
- **付费率用付费玩家基底不用活跃**✓✓✓(老服免费流失带歪,实测17.8%→49.2%假象);转化率漏斗分母=到达该阈值的窗口付费玩家。
- **R级固定档**✓✓✓:超R≥$1000/大R $200-999/中R $50-199/小R $1-49/非R=0(P2/X3口径,X2略有中大R细分)。**R级快照取节日开始前一天**(避免用活动期内数据造成因果倒置)。每档带付费率/ARPU/ARPPU/占比四件套。
- **服数不同只比率不比绝对值**✓✓✓。绝对值(流水/人数)跨不同服数不可比。
- **模块按名字语义归类,不靠id段**✓✓✓(BP/GACHA/七日/掉落复用旧id,dim_iap名字常是旧节日的;只剔真·往期残留=名字含别的节日/年份)。
- **口径必须显式声明**:单服vs全服、含日常vs仅节日礼包、活跃分母定义,都写进报告 ✓✓。
- **合服:配置服数≠活跃出单服数**✓✓(按id聚合流水不丢=钱记在存活服;按服数算单服指标要活跃出单服)。
- **货币口径**✓✓:Trino iap_price(USD)主口径;Datain pay_price≈USD×2、代币actual_charge=USD×100;跨口径只比方向不比绝对值。X3收入公式=usd/TOKEN取actual_charge否则pay_price(⚠️TOKEN的actual_charge是代币单位×100会爆)。
- **达成率=实际人均产出/设计目标**,用来区分"设计问题"还是"活跃度问题"✓✓。
- **异常值处理**✓✓✓:大R集中付费的服单独标注或排除出聚合(否则翻转结论);样本n<15标"波动大";±1单能改变结论的模块必须标波动性。
- **服体分层**✓✓:单服收入看中位数不看均值(被大服拉高);大服(万级DAU)与小服(<500)参与率不可比,分组列。

### ★按模块口径 → 见模块库
每种模块一套固定的窗口/分母/分析框架/踩坑,全部在 **[[reference-data-analysis-module-registry]]**(模块库,16+ 张规则卡,按 整体层/礼包/养成投放/参与产出/消耗回收/事件驱动 分组)。分析每个模块前先翻它的卡,**禁承袭上一个模块的范围**——这是"范围瞎搞"的根治点。库里没有的模块=现建卡。

## 三、流程层（怎么做·步骤/模板）

### 归因法（二选一,视有无holdout）✓✓✓
- **匹配对照法(有holdout)**:按W2的R级结构/DAU/大超R人数三维匹配实验组vs对照组,基准付费率对齐后(7.04% vs 7.02%)算净增。
- **跨期基准法(全量上线无holdout)**:vs上期同生命周期批次,两期用完全相同查询/窗口重算(先复刻上期数验证吻合再比)。
- **准自然实验**:取相邻同长度节日周期,先验证全服大盘几乎持平(-0.2%),差值即模块净效果;或加料前/后同款SKU对比。
- **净增归因拆解链+自洽验证**:对照自然变化→实验实际→净贡献(实验−对照)→拆"礼包直接贡献vs存量逆转";最后自洽验证(首单22人÷W3 DAU 2088=1.05%,与归因+1.05ppt对上✓)。
- **双口径交叉验证**:Trino主口径出结论+Datain二次验证,绝对值不求齐,**方向一致即通过**。

### 时间窗口 ✓✓✓
各服按**自身开服日对齐**(D0=开服/活动起,不用日历日;新服滚动上线尤其关键);生命周期对齐取"D0时服龄同阶段"的服(过D35成熟服)排除新服爆发期;窗口未跑满的服(仅3-6天)排除或标注;跨节日复用包/窗口外产出剔除。

### 服龄/投放时机 ✓✓
按"活动开始时服龄"每10天分段画渗透率曲线找拐点(尼罗超R皮肤D20-29低谷16.7%→D30-39拐点40%→皮肤类D21偏早建议D45+);用originSeaArea(海域解锁1→2→4→8)量化进度=外显价值容量;新老服人群独立无饱和传导,重上按新服口径规划。

### 报告结构模板（结论先行）✓✓✓
Hero一句话结论 → 3-4个KPI卡 → 三归因章节(总收入/付费率/ARPPU) → 模块分tab(带星级+保留/优化/重构标签) → 下期建议(P0/P1/P2) → 附口径说明。逐模块深挖章定式=章级大结论(黄框)+胶囊切换视图+每视图一条小结论(蓝框),一次显示一个视图。

### 结论呈现 ✓✓✓
- **三段式(每结论必备)**:🤖[数据层]客观陈述 → 👤[判断层]一句大白话点评(即使"没变化/持续观察"也写) → 🔧修改建议。
- **判词化+色标**:每模块一句话判词配[正常绿/关注橙/异常红]或达成✅/未达成❌;标题="结论N·模块名·一句话判词"+nav pill导航。
- **图+一句话**:每条结论=一句话判词+数据锚点+配图,成对出现先结论后图;禁纯文字长段、禁裸图无结论、禁"定位/本质上"无数据抽象话、分析口头语不进报告("对打"→"历史数据对比")。
- **单模块回归页必备设计回溯章**:三支思维导图(礼包设计/流程体验/数值设计),叶卡=名称+徽章+一句话+锚点跳转(禁长文);大结论逐点带章节跳转。
- **增长归因框(ASCII)**:共有模块(老/新/±%)+新增模块(纯增量)+总收入(±%),末句"X%增量来自新模块";**归因链ASCII**:活跃N人逐层↓缺口,落到根因定位最大缺口层。
- **诚实标注盲区("待人工补充清单")**:数据覆盖不到的决策项(流失根因/下期玩法)单列声明,防"数据假装能回答一切"。
- **末尾优化动作带优先级/状态**(P0/P1/P2 或 ✅已确认/💡建议/⚠️待验证),非开放式建议;优化外推标"AI外推非实测"+假设+风险。

### 受众多版本（同一套数据不同包装）✓✓✓
内部详版(全表全服) / 结论先行版(KPI+tab) / 发行版(加侧边栏导航、措辞收敛) / **给+2版(只留四类:总额/涨幅%/ARPU/节日占比)**;+2版=每提升点一卡(一句话功能+2-3大数字+口径小字+真机截图),动作按节日分组时间线,别人的活动进汇报必显著标注owner,增长太小(<10%/非四位数)不上。

### 日报监控 ✓✓
节日期间按D0..Dn每天出HTML日报+latest指针,跟首销脉冲(D0冲高付费率/ARPU翻倍→3天回落到略高于节前→整段仍高于自然趋势线)。脚本=`skills\x3-festival-monitor\x3_festival_daily.py` / `skills\x2-festival-monitor\x2_festival_daily.py`(模块映射真源)。

### 数据源映射
- **X3**:Trino `v1090` — ods_user_order(付费,user_id非uid/server_id都VARCHAR)/ods_user_asset(资产,asset_id前缀Item_)/ods_user_login(活跃)/ods_user_activity(activity_step判BP等级)/dim_open_server(服龄)/dim_iap(名称价格)。
- **X2**:Trino `v1089` — ods/dl_user_order/ods_user_asset+dim_asset(change_type=1获取2消耗)/ods_user_daily/ods_user_battle(2 PVE/3 GVE)/ods_user_event(counter,json_extract_scalar)/ods_user_activity。
- **P2**:Datain `v1041`(国际版hive.v1041) — ods_user_order+dim.iap(无activity_id,子活动收入靠SKU反查=估算)/ods_user_asset(reason_id过滤)/ods_user_task(阶梯留存)+ods_user_activity/activity_result双表交叉/da_user_rlevel_pay_ratio(R级)。
- 收入公式统一:`SUM(CASE WHEN currency_type IN ('usd','TOKEN') THEN actual_charge ELSE pay_price END)`,pay_status=1。

## 四、踩坑铁律（被推翻重来的,最值钱）
1. **ARPPU口径掩盖渗透真相**(三游戏都栽过):用"流水/付费人数"看得"ARPU没回升"反结论,换"流水/DAU"才见付费率在涨。**先用/DAU口径拆渗透vs深度**。
2. **大R集中服不排除会翻转结论**:某服大R单日集中付费,进聚合让实验组"看起来衰减更多",险误判活动无效。
3. **付费率累计vs日均给相反方向**→跨期不可比,只看同期趋势。
4. **复用旧id导致模块归类错**→按语义归类只剔真残留。
5. **跨节日复用包/窗口外产出不计入本期**(许愿池集中D35-41卖落在窗口外);窗口未跑满的服排除。
6. **集卡不加create_time过滤→历史积累高估收集度**(10万历史玩家算进本期);**无效包陷阱**(近半发包量不产出目标卡,先确认哪些包有效)。
7. **session/埋点vs数仓打架以数仓为准**:先锁game_cd(国际版vs CN=1076)、时间、表名三个口径维度找差异根源。
8. **"全参与全完成"设计假设是系统性高估源**:实际参与率(10-60%)×完成度(~50%)双打折,饱和度系统性偏低30-50pp;修正=给设计模型引参与率折损系数。
9. **BP等级靠道具量×暴击期望反推有偏差**:必须标注,有后台字段优先用字段。
10. **老服首轮买家数不能预估重上/新服**:新老服人群独立,新服疲软是需求侧进度不足(大地图未开)非老服饱和传导;重上按新服口径。
11. **DAU大跌别直接归因缺口**→先看付费盘动没动(DAU−29%但付费盘−3%,流失的是非付费/轻度)。
12. **组队/前置门槛会让整条产出链归零**:凡带组队/行军前置/累充阈值的渠道,先查门槛是否卡死目标人群。
13. **shop_order≠VIP商店**(X2:城市NPC订单系统,与shop_order_vip独立)。
