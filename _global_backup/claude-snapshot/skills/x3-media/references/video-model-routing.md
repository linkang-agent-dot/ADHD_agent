> **强制**：任何视频生成请求，派 worker 前主 agent 必须过一遍本文件。
> 背景：config.json 的 `preferred_video_model` 曾误导选型（vidu），实际历史定版按**视频类别**分流。
> 深挖版知识库：memory `reference_x3_hero_skin_video_production`（皮肤视频 §四/§七/§八）。

## 1. 类别 → 模型路由表（按历史定版归类，持续维护）

## 2. 生成前审查（主 agent checklist）

1. **归类**：本次视频属于上表哪一类？（有角色脸 → seedance 系；纯物件氛围循环 → kling fflf）
2. **查先例**：`state/history.jsonl` grep 同类关键词 + 对应 KB 产物目录，有定版先例照抄参数（模型/时长/规格）。
3. **规格锚**：落库视频先找同槽位现成 mp4 用 ffprobe 定规格（如 UITieredPack 头图锚=deepsea_decoration.mp4 810×1080 h264 5s）。**真标准=该弹窗/槽位的视频框尺寸**，无统一值。
4. **首帧**：图生视频一律先出/找一张构图完整的首帧图（icon 直接喂会画面稀疏），循环类首帧=尾帧。
5. **构图（礼包头图类）**：主体物件 ≈55% 画宽、重心在上 1/3、下方留氛围空间——主体满幅居中会被打回（2026-07-27 马戏门票 v1 实例）。首帧就按这个出，别等视频摇完再返工。

## 3. 产物验收（落库前必过）

| 检查项 | 标准 | 方法 |
|---|---|---|
| 循环接缝 | 首尾帧平均像素差 <3 好 / <8 可接受 | cv2 抽首尾帧算 diff |
| 无文字 | 画面零文字/字母（i18n 硬伤） | 抽帧目检 |
| 规格 | 对齐槽位锚（分辨率/时长/h264/yuv420p/无音轨） | ffprobe |
| 压缩落库 | **commit 进 client 仓必走** `client\Tools\VideoTools\compress_video.py -i <f> --no-backup`（过 pre-commit video_policy 钩子）；KB 侧展示片迭代用 GRFal `video_compression` | 实测 5s 压到 <1MB |
| 归档 | 原片+定版归 KB 固定路径；落库文件名=DK 去前缀 | — |

## 3.5 ★GIF/动图统一管线（2026-07-27 用户裁决，强制）

**所有 GIF 动图 = 先出视频 → 切帧 → 合成 GIF**。禁止以下歪路（已实操被打回并从知识库清除）：
- ❌ 静态图假动效脚本（squash-stretch/切变摆动，`_gen_emote_gif.py` 老法）——整图纸片式扭动，观感假
- ❌ AI 4×4 sprite-sheet 逐帧表转 GIF（dynamic_march_emoji 的 sheet_to_gif 路线）——帧间一致性赌运气

正路（透明 GIF，如聊天表情）：
1. 主体贴纸合成到**纯绿幕底**做首帧 → 按 §1 路由出视频（角色表演=seedance）
2. ffmpeg/cv2 抽帧（目标帧数 12-16，挑完整动作循环段）
3. 逐帧色键抠绿（`chroma_key_remove.py` 家族）或 GRFal `video_remove_background`
4. 合成 GIF：160×160、`disposal=2`、**LSD background==GCE transparency + 透明调色板项设白**（UniGifDecoder 铁律）
5. 验收：帧间连贯 + 首尾循环 + bg==trans + 尺寸在现役带宽（100-270KB）

## 3.6 ★长时段「变身/换装」类视频：必须给参考图，不能只给文字（2026-07-28 马戏节皮肤实证）

**现象**：10s 换装演出视频（紫金魔术师 → 脱外套 → 内搭翻金），变身后的造型**纯靠 prompt 文字描述**让 seedance 发挥 →
前 2s 完美还原首帧，**4s 后彻底跑飞**：礼帽消失／发型换成超长直发／脸变成通用美女／题材从「马戏魔术师」漂成「金色纱翼仙女」／
金色出成塑料死金／马戏元素（燕尾、灯泡滚边、紫金体系）全丢。

**根因**：模型在长时段变化里**会持续漂移角色特征**，文字约束（`predominantly brilliant gold`、`veils unfurl`）
会被它按自己的先验补全成最常见的意象（金色 + 飘纱 ≈ 仙女/女神）。**首帧只能锁住起点，锁不住 5s 之后。**

**做法**：
1. 先用 gpt 出一张**变化后造型的参考图**（可控、可挑、可反复改），确认造型对了
2. 视频生成时**首帧 + 该参考图一起喂**，prompt 描述过渡过程
3. 用户裁决（2026-07-28）：**给参考图即可，不必锁尾帧**——锁死会牺牲 AI 的过渡发挥；给方向就够
4. 参考图 prompt 要把「不能变成什么」写死（本案：NO wings / NO gown / NOT a fairy or goddess / KEEP the top hat），
   光写「要什么」不够——模型跑飞的方向恰恰是它先验里最强的那个意象

**附带教训**：worker 自述「变身真实完成／金色质感良好非死金／红发对比清晰」三条与实际画面全部不符。
**成片验收一律主 agent 自己抽帧目检**，别采信 agent 的文字结论（同 memory `feedback_subagent_result_injection`）。

## 3.65 ★seedance 双参考图：必须用「元素参考,元素参考」（2026-07-28 实证，含一次错误结论的修正）

**seedance 支持双参考图**，但 `ref_types` 的组合方式是硬约束：

| ref_types | 结果 |
|---|---|
| `"元素参考,元素参考"` | ✅ **可行**，两张图都作为方向参考生效（马戏节皮肤 v2 实证：第二张金色造型图的服装/配饰完全落实到成片） |
| `"首帧图像,元素参考"` | ❌ **服务端同步拒绝**（提交阶段就打回，不进异步队列）。报错原文：*"当前所选模型「即梦豆包2.0」不支持首帧+元素参考生视频，可改用：快手Kling, Luma Ray 3.2"* |

> 🪤 **我曾据这条报错错误地下结论「seedance 不支持双参考图」并写进本文件**——实际是**不支持混合模式**，
> 两张都标「元素参考」就通。**教训：拿到"不支持X"的报错时，先确认它否定的是「整个能力」还是「某种参数组合」**，
> 别把参数问题升级成能力缺失，会白白换模型、白跑一轮。

**这个模式恰好实现「给参考但不锁死」**：两张图都是同等地位的元素参考，不锁像素级构图，模型仍有发挥空间。
马戏节皮肤 v2 实证效果**优于写死的脚本**——原脚本写「外套化烟消散」，模型自己演绎成了「魔术师双手展开斗篷亮相、
金色演出装在斗篷中间显露」，是更地道的魔术手法。**发挥空间是有价值的，不必一上来就锁尾帧。**

**所以「变身/换装」类的推荐做法**（覆盖 §3.6 的部分结论）：
1. 先出一张**变化后造型的定稿参考图**（gpt，可控可挑）
2. seedance + `ref_types="元素参考,元素参考"`，首帧图与目标造型图一起喂
3. prompt 里把「不能变成什么」写死（§3.6 那条仍然成立）
4. 不必上 kling fflf 锁尾帧——那会牺牲模型的过渡发挥

⚠️ **模型名拼写**：GRFal 工具侧实际值是 `seadance`（不是 `seedance`），是同一个模型的拼写变体，调用时以 `seadance` 为准。

### 🚫 别再为「双参考图」去试 kling（2026-07-28 结论）
撞上 seedance 混合 ref_types 报错时，很自然会想「那就换 GRFal 建议的 kling 首尾帧吧」——**这条路已经走过，结果是废弃**：
kling 版即便两端造型都锁死，**动作依然被压死、变身过程平淡**（用户原话「kling 不行，拉胯了，还是走 seedance」）。
kling 唯一亮点是飞吻/噘嘴类嘴部动作做得好（它 warp 嘴的老毛病在这个动作上反成优势），但整体动态远不够。
**正解是回到 seedance 并把 ref_types 改成「元素参考,元素参考」**，不是换模型。

## 3.68 ★要抠透明的视频，prompt 必须强约束背景（2026-07-28 实证）

**现象**：同一个 prompt 并行双发（v5a/v5b），**背景分岔了**——v5a 保持白底，v5b 自己把背景改成了「暗场舞台+顶部聚光灯」。
prompt 里写的是 `plain white background`，但同时又写了 `BIG theatrical stage act`，模型就顺着「舞台」这个词自行补了场景。

**为什么这是问题**：该槽位是 **SBS 透明格式**，背景终究要抠掉。所以自行加的舞台氛围
**在最终成片里一点都留不下**，纯属白生成，还额外增加了抠边风险（暗场比白底难抠，红发边缘/金色反光处最易吃边）。

**做法**：
- 凡是下游要 `video_remove_background` 的视频，**背景要求必须写成强约束**：
  `plain solid white background, completely flat and empty — NO stage, NO scenery, NO spotlights, NO environment`
- 同时留意 prompt 里**其它词会不会诱导出场景**（本案就是 `theatrical stage act` 招来了舞台）。
  想要「舞台感」而又要抠图，正确写法是**把光打在人身上而不是画出场景**：
  `strong top light and warm rim light ON HER BODY, but the background stays plain and empty`
- 💡 反过来，**人物身上的舞台打光是会随人物一起保留的**，抠出来比平光版立体——所以「氛围」要靠打光实现，不靠背景。

**顺带**：这也说明**同 prompt 并行双发不只是抽卡运气**，两版可能在构图/背景这类结构性的地方分岔，
挑版时除了看好不好看，还要看**哪版对下游工序更友好**。

## 3.9 ★SBS 透明视频「该不该剪」只看 alpha 半边，别看彩色半边（2026-07-28 马戏节皮肤实证，返工一次）

**翻车经过**：皮肤演出视频结尾有一团紫色烟雾，用户说「紫色烟雾结束部分还是得剪掉」。
我抽帧看**彩色半边**，发现烟从 8.4s 就开始渗进来，于是剪在 8.625s ——
**把紧随其后的飞吻演出（8.8s 手到唇边 → 10.0s 向外送出）整个切掉了**，用户随即报「你把飞吻也给切掉了」。

**根因**：SBS 是「左彩色 / 右 alpha」双联视频，**游戏里只渲染 alpha 蒙住的部分**。
实测该片 alpha 非零占比从 8.0s 到 10.5s 稳定在 **21.8%（= 人物本身）**——
**那团紫烟压根没进 alpha，游戏里根本看不见**。彩色半边好看不好看，与最终观感无关。

**正确判据（剪 SBS 视频前固定跑这一遍）**：
```python
# 逐帧算 alpha 非零占比，找"人物剪影被破坏"的那一帧，而不是"彩色半边变脏"的那一帧
a = cv2.cvtColor(frame[:, W:], cv2.COLOR_BGR2GRAY)   # 右半 = alpha
frac = (a > 30).mean()
```
- 占比**稳定** = 剪影干净，可以留；
- 占比**下降**（本案 10.62s 起 21.8%→17.5%）= 前景元素开始把人物**吃出破洞**，必须剪在这之前；
- 占比**暴涨**（本案 11.0s 起 →64.8%）= 烟雾整个进了 matte，画面废掉。

**第二道判据（彩色半边此时才有用）**：只统计 **alpha 内**像素的偏色，判断人物有没有被雾"洗白"。
本案用 `B-G`（金色 B 低 G 高 → 负值大；紫雾会把它拉向 0）：
9.0s = -20.8（纯金） → 10.3s = -13.0（可接受） → 10.5s = -4.5（明显发灰）。
**最终剪切点 = min(alpha 破坏点, 颜色可接受点)**，本案取 10.33s。

**顺带纪律**：重剪一律**从原片（未剪的 `.bak`）重来**，不在已剪版上二次剪——二次编码叠加，且剪切点无法往后放。
所以第一次剪的时候就要**保留原片备份**（本案 `_full12s.mp4.bak` 救了命）。
